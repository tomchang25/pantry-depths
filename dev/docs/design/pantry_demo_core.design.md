## 一、關卡不得卡死

- 障礙物必須可被玩家通過，包括但不限於填平和拆除。
- 障礙物最好本身就提供遊戲機制——提供彈藥，或提供額外的死亡機制。
- 迷宮只是氛圍和機制的來源。不要給玩家迷路的機會，用輪廓投影解決。
- 不准有卡死的關卡。目前唯一的危險點是玩家開局被水坑圍起來，強制限制水坑不能圍成圓即可。

### 輪廓投影的分界

**投影負責「不迷路」，不負責「知道要去哪」。地形投影，目標不投影。**

| 對象             | 投影                       |
| ---------------- | -------------------------- |
| 地形、牆體、水坑 | 一律投影                   |
| 下層樓梯         | 主要目標完成後才開始投影   |
| Extraction room  | 不投影，得自己找           |

外接房只有 4 間，最多開 4 扇門就找完，搜索成本有上限，不會退化成瞎逛。

## 二、敵人

AI 必須簡單。敵人朝玩家移動：5 格外照 grid 巡路，5 格內直接朝玩家衝。

越下層越強，兩條軸：

- 特定 archetype 種類到某個深度才開始生成。
- Enemies 帶 Level，影響攻擊、防禦、血量。

### Level 的來源

全域計時，**下樓不歸零**。

| 來源 | 等級      |
| ---- | --------- |
| 時間 | +1 / 分鐘 |
| 下潛 | +5 / 層   |

## 三、右鍵：抓取

右鍵唯一的作用是抓取，抓取即使用物品。所有特殊效果都綁在被抓取的物品上，右鍵本身沒有任何變化，也不做替換。

現有物品：敵人、木棍、石塊、飛斧、炸彈。

未來預定：

| 物品   | 說明                     |
| ------ | ------------------------ |
| 標槍   | 對標木棍，但改由敵人掉落 |
| 火法術 | 取代炸彈                 |
| 冰法術 | —                        |
| 鐵扇   | 擊退敵人                 |
| 吸塵器 | 拉取敵人                 |

## 四、武器：Core 與 Fragment

主體叫 **Core**，碎片叫 **Fragment**。

### Core

武器的基底。武器之間的差別不是單純攻擊力不同，而是決定武器素材怎麼運作。

- 短劍：快、短距離、三連擊
- 斧頭：慢、範圍大
- 戰錘：慢、附帶擊退
- 長矛：直線穿刺、保持距離

普攻（左鍵，右手武器）要可以在準備階段替換。

Core 帶**隨機詞綴**。首版四條，全部沿用既有機制：

| 詞綴     | 掛點                   |
| -------- | ---------------------- |
| 攻擊傷害 | `meleeDamage()`        |
| HP       | `player.maxHp`         |
| 投擲傷害 | `thrownImpactDamage()` |
| 初始 Bless | `grantBless()`       |

Clean Core 的 range 單向正值；Cursed Core 雙向——可能更好，也可能更爛。

詞綴和 §五 的 Infinite Bless 掛的是同一組數值鉤子，只是來源不同。做一份 modifier 目錄三方共用，不要寫兩套。

> 實作備註：`thrownImpactDamage()` 目前直接 `return meleeDamage(world)`。投擲傷害要當獨立軸，得先拆掉這個委派，否則它和攻擊傷害是同一條。

### Fragment

附加的效果。暫時直接用 Bless 系統實作，等於開局直接贈送 Bless——Fragment 和 Bless 至少目前是同一個池子共用。

Fragment 和 Core 可以隨便搭配，一個武器最多裝 3 個 Fragment。

## 五、Bless

兩層，不做溢出特判。

| 層                 | 內容                         | 抽完之後       |
| ------------------ | ---------------------------- | -------------- |
| **Unique Bless**   | 各自是獨立機制               | 抽完就進下一層 |
| **Infinite Bless** | 可疊加的數值 buff，多種類    | 永遠抽得到     |

Unique Bless 要加進欄目的項目：

- 第三刀爆炸
- 擊殺後一段時間內加速，可疊加並重置時間
- 被打有機率反傷
- 普攻有機率冰凍
- 正面無視傷害
- 血量鎖死 10，但閃避 99%
- 增加掉落拾取物機率
- 法術等級

Infinite Bless 首版種類：maxHP / 攻擊傷害 / 投擲傷害 / 移動速度 / 攻擊範圍。

Unique 抽完就抽 Infinite。**Bless 不夠就把 Infinite 的種類做多，不是去做額外處理。**

> 實作備註：現行 `grantBless()` 抽不到就 `+25 maxHP` 的寫死分支要取消，改成往 Infinite 目錄抽。

## 六、地圖

半隨機半手作。一律 **1 大 + 3 小 + 1 撤離房**，共 5 塊拼接而成。

**拼接方式**：大地圖擺中間，21×21 有四條邊，三個小地圖和撤離房各佔一邊，直接邊對邊貼上去，然後開個洞破磚牆連通。

```
                  [ Sub ]
   [ Sub ]   [ Main 21×21 ]   [ Sub ]
              [ Extraction ]
```

**大地圖 21×21**：必定包含下層樓梯，由主要目標上鎖。原祭壇移除。

**小地圖 7×7**：目前三間全上，不抽籤。

| 小地圖     | 作用                                                             |
| ---------- | ---------------------------------------------------------------- |
| 溫泉       | 回血                                                             |
| Bless 祭壇 | 進範圍撐 5 秒 → Bless。受擊不中斷，只看人在不在範圍內            |
| 詛咒祭壇   | 打壞 → Cursed Cache                                              |

砸的給詛咒，守的給祝福。

**撤離房 7×7**：撤離樓梯，每層必有，全程開啟，不受 task 影響，不投影。

地圖可以手工製作後有機率被抽到，或完全隨機。手工地圖主要用來當新奇感，例如：下層樓梯在正中間，外圍 4 格護城河，玩家得一路填過去。

## 七、Cache

蓋住的獎勵物。在 run 裡面只知道它是什麼類別，撤離之後才鑑定。

| Term             | 來源     | 構成                     |
| ---------------- | -------- | ------------------------ |
| **Clean Cache**  | 主要目標 | 80% Fragment / 20% Core  |
| **Cursed Cache** | 詛咒祭壇 | 40% Fragment / 60% Core  |

Cursed 的內容物更好，也更險：

- Fragment 帶 **2+ Bless**
- Core 的 attribute range **雙向拉大**——可能更好，也可能比 Clean 還爛

雙向 range 就是詛咒本身，不另外做一張負面詞綴表。

## 八、使命（task）

統一叫 task，省得以後想不開要做 NPC 和 Quest 系統。

每層 **1 個主要目標 + 3 個次要目標**。

| 目標     | 數量 | 給什麼                                          | 生效                       |
| -------- | ---- | ----------------------------------------------- | -------------------------- |
| 主要目標 | 1    | 下層樓梯解鎖並開始投影 ＋ 1 個 Clean Cache      | 樓梯即時；Cache 撤離後     |
| 次要目標 | 3    | Bless                                           | 即時                       |

下潛不再送 Bless。撤離樓梯不受 task 影響，隨時可走。

條件形式：

- 擊殺定量敵人
- 使用特定方式擊殺定量敵人
- 到達某格站 3 秒
- 拆除定量牆體
- 找到鑰匙並成功丟到開鎖祭壇中
