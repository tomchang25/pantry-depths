框架範本。 各節在對應 child 落地後補齊。里程碑收尾時本檔必須能獨立回答第 ④ 與第 ⑤ 節的兩個問題，否則 src/content/ 就只是一堆沒有註解的數字。

① 層與邊界

邊界由 .dependency-cruiser.cjs 機械強制，並列入 npm run verify。 違反邊界代表程式碼放錯位置，修法是移動程式碼，不是放寬規則。

src/core/ — 確定性規則：格子、朝向、回合結算、雙向 max(0, 攻擊 − 防禦)。不 import 任何其他層，不碰 DOM。
src/content/ — authored 數值：敵人表、四扇門的 effect、五張烘焙地圖、sprite 的 scale 與 anchorY。只透過 core 契約定型。
src/presentation/ — Canvas 2D raycaster、程序化環境材質、sprite、VFX、音效。 從 core snapshot 讀，不回寫。
src/runtime/ 輸入到 command、snapshot 路由 · src/ui/ HUD DOM overlay · src/harness/ 確定性 scenario 與 debug API · src/app/ bootstrap，唯一的 harness 接線點
待補：實際的 import 方向圖與每層行數。

② 一次 Action 的完整流程

從按下 W 到畫面更新。這是全遊戲唯一的狀態變更路徑。

待補（pantry_feel_01 落地後）。必須涵蓋：輸入緩衝與補間鎖、command 產生、core 結算順序、反擊掃描、snapshot 發佈、presentation 補間、HUD 更新。

目前已知的固定規則：反擊在補間開始時就結算完成，動畫只是表現。 動畫時間永遠不影響遊戲狀態。

③ 確定性單向閥

戰鬥不含任何隨機數。相同輸入序列永遠產生相同結果——這是平衡模擬可行的前提，也讓每一次 playtest 死亡都可以精確重現。

待補：core 為什麼不能碰 DOM、harness 如何在沒有瀏覽器的情況下重播整條路線。
